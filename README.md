# 🎓 أرشيف امتحانات كلية الهندسة – جامعة الجفرة

موقع إلكتروني احترافي لأرشفة **امتحانات السنوات السابقة** لكلية الهندسة – جامعة الجفرة.
يتيح للطلاب تصفح الأقسام والمواد، والبحث، ومعاينة وتحميل ملفات الامتحانات (PDF)،
مع **لوحة تحكم إدارية كاملة** لإدارة كل المحتوى.

> **إعداد:** جهاد سالم أحمد

---

## ✨ المميزات

### واجهة الطلبة (`index.html`)
- تصميم جامعي عصري وفخم بالكامل بالعربية ودعم RTL.
- عرض الأقسام ← المواد ← امتحانات السنوات السابقة (مرتبة حسب السنة والفصل).
- **معاينة ملفات PDF داخل الموقع** + تحميل مباشر.
- **بحث سريع** موحّد عن القسم أو المادة أو الامتحان.
- **الجداول الدراسية في صفحة مستقلة** (`timetables.html`) تُفتح من زر **«الجداول الدراسية»**
  في الواجهة الرئيسية أو من أيقونة الجدول في الترويسة — لتوفير مساحة الصفحة الرئيسية وإبقائها نظيفة.
- داخل صفحة الجداول: بطاقات الأقسام، وكل جدول **جدول حقيقي** (لا صورة) مُصمَّم للهاتف والحاسوب
  مع تمييز اليوم الحالي، ويُفتح بضغطة على زر **«عرض الجدول»** في نافذة عرض كاملة (وعلى الهاتف تملأ الشاشة).
- **المنهج والشيتات**: ملفات PDF لكل مادة (منهج / شيت / ملف) يضيفها المدير، ويشاهدها الطالب مع المعاينة والتحميل.
- **إدارة الجداول من لوحة الإدارة**: إضافة جدول، تعديل أيامه وفتراته ومواده، إخفاؤه أو حذفه — ويظهر للطلبة فوراً.
- متجاوب تماماً مع الهاتف والحاسوب، مع حالات تحميل ورسائل واضحة.

### لوحة الإدارة (`admin.html`)
- تسجيل دخول آمن عبر Supabase Auth.
- شريط جانبي **مُقسَّم لمجموعات** (نظرة عامة · إدارة المحتوى · النظام) + زر إظهار/إخفاء القائمة على الهاتف.
- إحصائيات (أقسام / مواد / امتحانات / ملفات).
- إضافة وتعديل وحذف: الأقسام، المواد، الامتحانات.
- **المنهج والشيتات**: إضافة منهج/شيت/ملف لأي مادة (PDF أو عنوان فقط) مع المعاينة والحذف.
- رفع ملفات PDF مع التحقق من **النوع والحجم** (PDF فقط، حتى **50 ميجابايت**) وإظهار حجم الملف فور اختياره.
- استبدال ملف الامتحان وحذفه (مع حذف الملف من التخزين تلقائياً).
- جداول منظمة مع بحث وفلترة، ورسائل نجاح/خطأ بالعربية.
- **تأكيد قبل الحذف** لكل عملية.
- **سجل النشاط**: يسجّل آخر 200 عملية (إضافة/تعديل/حذف/دخول/خروج) مع إمكانية التصدير أو المسح.
- **النسخ الاحتياطي**: تنزيل نسخة كاملة (JSON)، أو تصدير كل جدول بصيغة CSV جاهزة لـ Excel (بترميز عربي صحيح).
- **تصدير CSV** من داخل كل تبويب + نسخ ملخّص الإحصائيات للحافظة.
- زر **تحديث البيانات** وزر **عرض الموقع** في الترويسة.

### الأمان
- **Row Level Security (RLS)** في قاعدة البيانات: الزوار يقرؤون فقط، والمدير فقط يكتب.
- **Storage Policies**: قراءة عامة لملفات PDF، والرفع/الحذف للمدير المسجل فقط.
- لا توجد أي مفاتيح سرية (`service_role`) داخل ملفات المشروع — فقط `anon` العام المخصص للمتصفح.
- 🔒 **الكتابة مقيّدة ببريد المدير**: نفّذ `supabase/restrict-admin-write.sql` لتصبح الكتابة
  لصاحب البريد في جدول `admins` فقط — حتى لو نجح أي شخص في إنشاء حساب لن يستطيع تعديل الأرشيف.
- 🚫 **أوقف التسجيل العام**: من Supabase ← **Authentication** ← **Sign In / Providers**
  ← أوقف **Allow new users to sign up**. (أنشئ حسابات المديرين بنفسك من Authentication ← Users.)

## 📅 إضافة جدول دراسي جديد

> **جديد:** يمكنك الآن إضافة وتعديل الجداول مباشرة من لوحة الإدارة
> (تبويب **«الجداول الدراسية»**) — ارفع/عدّل الأيام والفترات والمواد واضغط حفظ،
> ويظهر الجدول على الموقع فوراً. يتطلّب ذلك تنفيذ ملف `supabase/timetables.sql` مرة واحدة.
> الطريقتان التاليتان تبقى متاحتين لمن يفضّل التعديل على الملفات.

هناك طريقتان، وكلتاهما لا تحتاج تعديلاً على قاعدة البيانات:

### الطريقة 1 (المفضّلة): جدول نصّي حقيقي

افتح `js/timetables.js` وأضف عنصرًا داخل مصفوفة `SCHEDULES`:

```js
{
    id: 'it',                          // معرّف فريد (يُستخدم لربط الصورة الرسمية إن وُجدت)
    department: 'هندسة الحاسوب',
    term: 'فصل الخريف',
    year: '2026 – 2027',
    isNew: true,
    slots: ['9 – 11', '11 – 1', '1 – 3'],   // أوقات المحاضرات بالترتيب
    days: [
        // كل يوم: نفس عدد slots بالترتيب — اترك '' للفراغ
        { name: 'السبت',  courses: ['', 'شبكات الحاسوب', 'رياضيات متقطعة'] },
        { name: 'الأحد',  courses: ['برمجة 2', 'قواعد البيانات', ''] }
    ]
}
```

يظهر الجدول تلقائيًا كبطاقة أنيقة في قسم «الجداول الدراسية» **بدون عرض الجدول في الصفحة**،
وعند الضغط على زر **«عرض الجدول»** يُفتح الجدول الحقيقي في نافذة عرض كاملة،
مع تمييز **اليوم الحالي** تلقائيًا (وعلى الهاتف يتحوّل إلى بطاقة لكل يوم). الأيّام المتاحة: السبت، الأحد، الاثنين، الثلاثاء، الأربعاء، الخميس.

### الطريقة 2: صورة جدول

1. ضع صورة الجدول داخل المجلد `images/timetables/` (اسم بالإنجليزية بدون مسافات، مثال: `it.png`).
2. اختياريًا: أنشئ صورة مصغّرة بنفس الاسم + `-thumb` لتسريع التحميل (مثال: `it-thumb.webp`).
   *لو لم تُنشئها، استخدم نفس الصورة الكاملة في الحقلين.*
3. افتح الملف `js/timetables.js` وأضف عنصرًا جديدًا في مصفوفة `TIMETABLES`:

```js
{
    id: 'it',                              // معرّف فريد (بالإنجليزية)
    department: 'هندسة الحاسوب',            // اسم القسم كما يظهر للطالب
    term: 'فصل الخريف',                    // الفصل
    year: '2026 – 2027',                   // السنة الدراسية
    image: 'images/timetables/it.png',     // الصورة الكاملة (للعرض والتحميل)
    thumb: 'images/timetables/it-thumb.webp', // الصورة المصغّرة للبطاقة
    isNew: true                            // إظهار شارة «جديد»
}
```

4. احفظ الملف وحدّث الصفحة — سيظهر الجدول تلقائيًا مع عارض التكبير والتحميل.

> يمكن أيضاً الجمع بين الطريقتين: جدول نصّي في `SCHEDULES` مع عنصر في `TIMETABLES` بنفس `id`
> و`native: true` — عندها تُعرض بطاقة الجدول النصّي فقط (والضغط على زر «عرض الجدول» يفتحه في نافذة كاملة).

## 📚 إضافة منهج أو شيتات لمادة

بعد تنفيذ `supabase/materials.sql` مرة واحدة:

1. ادخل لوحة الإدارة ← **المنهج والشيتات**.
2. اختر المادة والنوع (**منهج** / **شيت** / **ملف آخر**) واكتب العنوان.
3. أرفق ملف PDF (اختياري — يمكن إضافة العنوان فقط، مثل «منهج المادة: الفصل الأول»).
4. اضغط **إضافة** — سيظهر للطلبة فوراً داخل صفحة المادة تحت قائمة الامتحانات، مع أزرار المعاينة والتحميل.

> حدّ الملف 50 ميجابايت، ويُرفع إلى نفس مخزن `exam-files` داخل مجلد `materials/`.

## 🚀 التشغيل في 3 خطوات

### 1) أنشئ الجداول والتخزين في Supabase
1. افتح [Supabase Dashboard](https://app.supabase.com/) وادخل إلى مشروعك.
2. من القائمة الجانبية اختر **SQL Editor** ← **New query**.
3. انسخ **كامل محتوى الملف** [`supabase/schema.sql`](supabase/schema.sql) والصقه.
4. اضغط **Run**.

> هذا الأمر ينشئ: جداول `departments` و `subjects` و `exams`، وسياسات الحماية (RLS)،
> وسلة التخزين العامة `exam-files` مع سياساتها، ودوال تحديث التاريخ تلقائياً.
> الملف آمن لتشغيله أكثر من مرة.

> **لميزة «المنهج والشيتات»:** نفّذ أيضاً الملف [`supabase/materials.sql`](supabase/materials.sql)
> بنفس الطريقة (SQL Editor ← Run). آمن للتشغيل أكثر من مرة، ويضيف جدول `materials` وسياسات الحماية له.

### 2) أنشئ حساب المدير
من Supabase: **Authentication** ← **Users** ← **Add user** ← **Create new user**
- **Email:** بريدك الإلكتروني
- **Password:** كلمة مرور قوية
- اضغط **Create user**

هذا هو الحساب الذي ستسجّل به في `admin.html`.

### 3) شغّل الموقع
```bash
# أي خادم ملفات ثابتة يعمل، مثال:
npx serve .
# أو
npx http-server -p 8000
```
ثم افتح: `http://localhost:8000`

> فتح `index.html` بالنقر المزدوج لا يعمل بسبب قيود المتصفح على `file://` — استخدم خادماً محلياً.

## 🔧 ربط مفاتيح Supabase

المفاتيح موجودة في [`js/config.js`](js/config.js). لاستخدام مشروعك الخاص عدّل السطرين:

```js
const SUPABASE_URL = 'https://YOUR-PROJECT.supabase.co';
const SUPABASE_ANON_KEY = 'YOUR-ANON-PUBLIC-KEY';
```

⚠️ **تحذير:** استخدم دائماً `anon public` key في الواجهة الأمامية.
لا تضع أبداً `service_role` أو `sb_secret_...` داخل أي ملف من المشروع.

## 🌐 النشر على GitHub (مجاناً)

### GitHub Pages — النشر التلقائي من الفرع
1. أنشئ مستودعاً جديداً على GitHub (**Public**، وبدون README).
2. اربط المستودع وارفع الملفات:
   ```bash
   git remote add origin https://github.com/USERNAME/REPO-NAME.git
   git push -u origin main
   ```
3. في المستودع: **Settings** ← **Pages** ← **Build and deployment**:
   - **Source:** `Deploy from a branch`
   - **Branch:** `main` — المجلد: `/ (root)`
   - اضغط **Save**
4. انتظر دقيقة، وسيظهر رابط موقعك في **Settings ← Pages**.

بعدها كل تحديث يُنشر بأمر واحد:
```bash
git add -A
git commit -m "تحديث"
git push
```
وتابع عملية النشر في تبويب **Actions** ← `pages-build-deployment` (يجب أن تظهر ✅).

> ⚠️ **لا ترفع الملفات من واجهة GitHub بالسحب والإفلات:** فهي تتجاهل ملف
> `.gitignore` وترفع الصور الأصلية الضخمة، ولا ترفع أي ملف/مجلد يبدأ بنقطة
> (مثل `.nojekyll`). استخدم `git push` دائماً — أنظف وأسرع.

رابط النشر سيكون مثل: `https://USERNAME.github.io/REPO-NAME/`

### بديل: Vercel
1. ادخل [vercel.com](https://vercel.com) ← **Add New Project** ← اربط مستودع GitHub.
2. اضغط **Deploy** (لا حاجة لأي إعدادات — مشروع ملفات ثابتة).
3. ستحصل على رابط مثل `https://your-project.vercel.app`.

> **ملاحظة GitHub Pages:** لأن الموقع يعتمد على Supabase عبر `fetch`،
> تأكد من إعداد سياسات RLS والتخزين (الخطوة 1) قبل النشر. المفتاح `anon` عام بطبيعته
> وهو آمن للنشر طالما أن RLS مُفعّل.

## 🧪 اختبار سريع بعد الإعداد

1. افتح `admin.html` وسجّل الدخول بحساب المدير.
2. أضف قسماً (مثال: «هندسة النفط»).
3. أضف مادة داخل القسم (مثال: «ميكانيكا الموائع»).
4. أضف امتحاناً: الاسم + السنة + الفصل + ملف PDF.
5. عد إلى `index.html` وتحقق من ظهور القسم ← المادة ← الامتحان، وجرّب المعاينة والتحميل والبحث.
6. جرّب التعديل والحذف (مع رسالة التأكيد).

## 🛠️ حل المشاكل الشائعة

| المشكلة | السبب | الحل |
|---|---|---|
| رسالة «جداول قاعدة البيانات غير موجودة» | لم يتم تنفيذ `schema.sql` | نفّذ ملف `supabase/schema.sql` في SQL Editor |
| «البريد الإلكتروني أو كلمة المرور غير صحيحة» | لا يوجد حساب مدير أو بيانات خاطئة | أنشئ مستخدماً من Authentication ← Users |
| فشل رفع الملف | سياسات التخزين أو حجم/نوع الملف | تحقق من سياسات bucket `exam-files`، والملف PDF ≤ 50MB |
| رسالة «حجم الملف كبير جداً» والملف أصغر من الحد | حد السلة في Supabase ما زال 10MB | شغّل `supabase/raise-file-size-limit.sql` في SQL Editor |
| الملفات لا تُعرض | السلة غير عامة (public) | اجعل bucket `exam-files` **Public** |
| لا تظهر البيانات للزوار | سياسات القراءة غير موجودة | نفّذ `schema.sql` كاملاً (يتضمن سياسات SELECT) |
| الصفحة فارغة عند فتحها بالنقر المزدوج | قيود `file://` | استخدم خادماً محلياً (`npx serve .`) |
